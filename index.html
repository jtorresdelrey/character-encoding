El ADN del texto digital

Para un ordenador, las palabras no existen; solo existen interruptores encendidos o apagados. El problema es que cada sistema de lectura interpreta esos interruptores de forma distinta.

Entender cómo se organizan estos datos es la única forma de evitar que tus traducciones se conviertan en basura digital.

Laboratorio de bits: la unidad mínima

Un byte es un paquete de 8 interruptores. Al combinarlos, generas un número decimal. Ese número es la «dirección» donde el ordenador busca cada letra.

Análisis técnico: comparación de estándares

Fíjate en cómo los caracteres básicos (A, a) coinciden siempre. Sin embargo, en los caracteres propios de cada lengua, UTF-8 fragmenta el valor original. Al comparar ANSI con UTF-8, verás que el valor real se preserva, aunque repartido en varios bytes.

El desastre del mojibake

El «mojibake» ocurre cuando guardas una palabra con un diccionario (codificación) y el programa intenta leerla con otro distinto. Es como si escribieras en español pero el lector aplicara las reglas de pronunciación del alemán: el resultado es un sinsentido.

A Codificar en...

Acción: INTERPRETAR

No tocas el archivo. Solo le dices al editor "cambia de gafas". Si el texto se arregla, es que los datos estaban bien. Es la primera opción a probar siempre.

B Convertir a...

Acción: TRANSFORMAR

Reescribes los bytes del disco. Peligro: Si conviertes un texto que ya se ve mal, guardarás el error para siempre. Úsalo solo cuando el texto ya se lea bien.

Supervivencia en código: escapado

A veces no puedes usar caracteres especiales directamente (HTML antiguo, Java properties). Usamos códigos de escape para representar la letra de forma segura con solo ASCII.

¿Por qué? Unicode es el "pasaporte universal". Al representar un carácter por su código numérico (ej. \u00F1), blindamos el texto contra errores de interpretación en cualquier sistema del mundo.
